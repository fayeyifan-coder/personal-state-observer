# Personal State Observer｜2026-10-28 新需求决定：低频数据交接，为电脑 API 分析服务

**需求已由使用者明确：手机记录是日常工作，电脑只是为了更深入调用 AI API 分析；每周一次甚至每两周一次数据交接足够。**

## 产品目标重排

1. **手机**仍是唯一权威记录库；离线观察不受 Netlify/API 影响。用户可随时手动导出完整备份。当前正式 main 具有 JSON 导出；加密 JSON 导出及安全只读预览位于隔离 Draft PR 中，尚不可误称正式已部署。
2. **传递周期默认 14 天、可选 7 天**。定义为用户在电脑成功本地解密且校验备份文件后，手动确认的“上次完成交接日期”，不是仅在手机点击导出的时刻。提前、逾期、手动临时交接均允许。绝不因为超期自动上传、自动删除或覆盖数据；日期提示可脱网计算。
3. **传输 MVP**：手机生成加密的完整备份文件，经用户选择的文件传输方式交给电脑；电脑在**本地**解密、校验、只读检查，并保留可恢复的完整历史。绝不为导入而默认执行现有 `restoreBackup`（它会清空目标表）。没有服务器、额外站点、PostgreSQL、持续在线或自动配对也能完成。
4. **分析频率 ≠ 分析时长**。每 14 天交接一次完整历史，电脑可分别选择最近 14 天、90 天、半年、一年等窗口。季节/周期分析需要更长的上下文，不能按传输周期裁掉历史。
5. **API 调用另设明确同意门槛**。电脑先本地计算数值趋势、缺失率和图表；仅在用户审阅字段、日期范围和实际要发出的内容后，才可选择将**最小必要数据**传给外部 AI API。API 提供商、地区、数据保留规则和费用还未选定。传给 API 的数据即使没有姓名，仍可能是敏感的健康信息；不能声称 AES-GCM 密文可被 API 直接分析。
6. **API 密钥不放入公开前端**：GitHub Pages/Vite 纯静态页面、public env 和浏览器代码不能安全保密长期 API 密钥。以后可选电脑本地程序或受保护的代理，并控制费用、日志和访问范围。不要把 API 密钥提交到 GitHub 或塞入公开页面。
7. **旧 Netlify 研发栈降级为可选增强**：P18 Draft PR #23–#28 的签名、CAS、服务器接入与托管成本研究可保留作为未来无人值守远程传输的安全原型，但不再阻挡“每周/两周完整备份→电脑只读分析”的第一版交付。现有 Netlify Free 剩余额度也不是必须消耗的项目预算。

## 本轮代码的具体范围

本 PR 独立从 `main` 起支，不叠加试验性云同步分支：

- `periodicTransferStatus(today, lastConfirmedDesktopImportDate, 7|14)` 是**纯离线日历计算**，默认 14 天；未交接标识、手动确认日期、日历合法性、设备日期倒退均显式处理。函数不写浏览器存储、不启动定时器、不联网、不推送通知。
- `buildLocalNumericAnalysisDraft(backup, from, through)` 仅从已校验、由调用方持有的完整 `AppBackup` 生成**临时只读数值分析草稿**。按日期筛选 `mood`、`energy`、`sleepDurationMin`、`sleepQuality` 和设备数值（睡眠/步数/心率/体重）；省略全部自由文本、未经选择的问答、期间标签、行 ID 和时间戳；重复日期拒绝；不读取 IndexedDB、不发送网络请求、不修改备份。
- 该草稿仍含日期和健康指标，属于**敏感信息**，结构里注明 `requiresExplicitExternalApiConsent: true`。这个标记是提醒未来 UI 获得独立明确授权，**不是**已经获得任何 API 上传许可。
- 单元测试验证跨月、闰年、7/14 天、手机只读/源备份不变、分析时间范围独立、重复日期失败及备注/姓名/ID 不被默认纳入。未连接 DataPage 交互，也未生成正式分析请求。

## 后续的最小产品路径

| 优先级 | 功能 | 放行条件 |
|---|---|---|
| P0 | 采纳已测试的安全加密导出和只读备份预览能力 | 独立复核/小 PR；先拿合成数据演练，不要求用户覆盖任何设备数据库 |
| P1 | 手机“准备交接”与电脑“只读接收”流程 | 首屏显示周期选择（14/7）、本地上次已确认接收日和本次文件范围；没有文件传输自动化或服务器依赖；用真实手机浏览器手动验收前不进 main |
| P1 | 电脑分析页与可审阅的 API 数据选择界面 | 本地分析正常；默认不上传。显式提示数据范围、字段、敏感性、预计调用成本；未经确认绝不发送 |
| P2 | 接入用户选定的 AI API（仅电脑） | 独立密钥保管/代理方案，API 计费上限与退出路径，独立用户批准；输出标注是相关性/假设而非医学诊断 |
| P3 | 如果手动交接的摩擦确实明显，再评估云端加密中转 | 重新核对 Netlify 可用额度及站点隐私；复用先前 Draft 安全研究，另行授权部署 |

## 不在本轮范围

- 不创建任何 Netlify/AWS 资源、数据库或外部 API 调用。
- 不添加双向编辑或自动同步、CRON 定时任务、浏览器后台推送。
- 不改手机的正式 IndexedDB、不导入真实记录、不合并到 `main`、不在 CI 放入个人数据。
- 不将任何数值草稿自动当作诊断建议，也不默认发送给第三方。

**结论：优先把“一次可信任的本地数据交接 + 可用的电脑 API 分析”做成产品，而不是把原型的高频在线同步视为必经之路。**
