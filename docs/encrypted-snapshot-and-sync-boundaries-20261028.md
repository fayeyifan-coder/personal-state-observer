# 手机主记录 → 电脑读取：加密快照 P2 交付与后续同步边界

日期：2026-10-28

## 本阶段（开发分支，不影响线上手机数据）

在现有安全差异预览之上提供**可选的本机加密 JSON 导出**和**本机解密后预览**。普通 JSON 导入导出仍可用，便于兼容早期备份；加密文件内包含每日记录、时期标记和设备数据，不改变数据库 schema。

- `src/services/encryptedBackup.ts`：Web Crypto AES-256-GCM（认证加密），PBKDF2-HMAC-SHA-256、600000 次迭代、随机 16 字节 salt、随机 12 字节 IV。每次加密生成新的随机参数，认证相关数据固定为 `personal-state-observer:encrypted-backup:v1`。
- 文件外层只含格式版本、算法标识、迭代参数、随机盐、IV 和密文；备份的日期、答案、时期名称、创建时间等均位于密文内部。文件名带导出日期，它本身不是机密。
- 加密密码只在当前页面交互中使用，不上传、不写入 IndexedDB、localStorage 或 GitHub；导出成功或成功解密后清空页面密码字段。JavaScript 内存不能保证字符串立即安全擦除。
- 保护边界：不少于 12 字符仅是低限，不代表一定强。强烈建议**长且唯一的密码短语**；密码遗失无法解密，密码太弱可能被离线猜测。该密码也不是登录账号或云端身份验证。
- 错密码、被篡改的密文、非预期版本/算法、明显超限文件必须拒绝；成功解密仍需 `parseBackup` 和现有差异检查，并经用户明确确认后才可调用事务内安全恢复。
- `MAX_BACKUP_PLAINTEXT_BYTES` 为 20 MiB，输入加密文件上限为 35 MiB。超过上限直接报错，不静默截断。
- 此功能并**不是自动云同步**：用户仍需自行通过文件传输把加密 JSON 带到电脑。手机端仍是唯一主要记录设备。

## 自动单向同步所需下一独立阶段（不得在本 PR 偷偷开启）

1. **独立测试环境**：需要与生产站点不同的 HTTPS origin，避免与正式手机 IndexedDB 共享存储；以虚构数据验证真实手机浏览器/已安装 PWA 更新。不要在正式站点覆盖用户真实数据库。
2. **后端与认证**：需要选择提供身份认证、授权访问和可撤销凭据的私有存储服务。不能把私有 JSON 当作 GitHub 仓库或 Actions artifact 的公开资料；静态 GitHub Pages 本身不提供私有快照后端。服务端只保存密文，客户端应锁定允许连接的服务端地址。
3. **发布协议**：手机拥有写入权限，上传加密完整快照；电脑默认只读下载。使用服务端生成的单调版本标识 / ETag 条件写入，禁止旧快照无提示覆盖新版本，保留受限数量的历史版本和人工回滚入口。
4. **密钥管理**：先做设备配对、加密密码或恢复密钥的安全交付、丢失密码处理、手机遗失后的设备撤销；不得靠硬编码共享密钥或把密钥放 URL 查询字符串。需要评估更合适的密钥派生策略以及低内存手机的性能。
5. **错误与离线行为**：网络失败不影响本地保存；上传失败可重试但不能误报已同步；电脑发现版本变化应先预览，不应无提示覆盖本机数据；可核验的校验和完整性认证、日志去敏及失败回滚必须纳入验收。
6. **双向同步**：目前不做。若未来允许电脑独立写入，则必须单独处理删除墓碑、冲突策略、离线队列、主时钟和早晚阶段字段；不能仅凭 `updatedAt` 做最后写入获胜。

## 合并条件

- `npm run test:encrypted-backup`、原有安全测试、`npm run build`、Chrome 隔离浏览器加密导出 / 错密码 / 篡改 / 解密预览 / 用户确认恢复全绿。
- 实体数量、日期和 `null` / `[]` 值往返不变；未授权时不写入 IndexedDB。
- 手机真实系统与 HTTPS origin 的最终验收尚待独立执行，用户明确同意前不将 PR 合并到 main。
