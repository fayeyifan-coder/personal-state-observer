# 备份差异预览验收清单（PR #2）

## 状态与边界

- 依赖 PR #1 的 `compareBackupCollections`；此 PR 为后续独立草稿，目标是 #1 的分支。
- 所有个人观察记录只在浏览器本地处理；本功能不上传，也不增加云端同步能力。
- **GitHub Pages 的生产站点仍来自 main**，不能直接在现有手机上看到本 PR 的效果。
- 不许通过“清除网站数据”“删除 IndexedDB”“卸载 PWA”来测试。
- 验收时使用**虚构数据**及与手机端生产域名不同的本地测试环境；真实用户备份不得提交到仓库或作为 CI artifact。

## 检查项目

1. 构建：`npm ci`、`npm run test:logic`、`npm run test:analysis`、`npm run test:backup-comparison`、`npm run test:backup-restore-policy`、`npm run build`。
2. 初次导入：目标端为空、虚构备份有 2 天数据 → “仅备份”=2，需人工明确确认才能恢复。
3. 安全追加：本机已有与备份完全相同的一天，备份多出另一天 → 展示“相同”及“仅备份”，允许人工恢复；原有日期内容不变。
4. 本机独有：本机有 10 月 27 日，备份没有这天 → 显示“仅本机”且**不显示确认替换按钮**。
5. 同日冲突：同一天但答案/早晚阶段不同 → 显示“内容不同”，不显示确认替换按钮。
6. 标签/设备冲突：同 ID 标签内容不同，或同日设备数据不同 → 不允许替换。
7. 损坏备份：同日期重复、不同日期共用同一个主键、备份缺少基本字段 → 禁止替换，保持本机记录。
8. 取消操作：选择文件并预览后关闭，或在浏览器确认框点取消 → 本机数据库不变。
9. 并发变动：预览完成后，另一标签页新增或修改本机数据，再点击恢复 → 事务内再次检测并阻止会丢失数据的替换。
10. 窄屏：在 320–390px 宽度检查表头、数字、长文件名、详情展开、按钮操作；不允许横向溢出遮挡重要内容。
11. 旧格式：无 `deviceData` 的早期 JSON → 仍能预览；已有本地设备数据时恢复需被拦截，避免数据被清除。
12. 导出：在预览前后都可导出最新本机 JSON；下载文件不得自动上传到 Github、Bark 或任何服务。

## 用户侧上线原则

先完成这张清单，并审查两条依赖 PR，再由用户决定是否合并。**不要直接在真实手机上试验可能覆盖数据的恢复动作。** 上线后手机仍是主记录端，电脑仍为辅；自动加密快照同步属于下一阶段。
