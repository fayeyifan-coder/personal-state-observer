# 个人状态观察器｜虚构站设备密钥本地试验（2026-10-28）

## 本轮范围

此前 **Netlify Private 登录**已经在 iPhone Safari 和电脑浏览器真实通过。但 Netlify 账户登录与手机设备授权是两回事：同一个账户下的电脑不得自动拥有发布权限。

本 PR 只在 `test/isolated-phone-lab-20261028` 的独立**虚构数据站**增加一块「设备密钥 · 本机测试（未配对）」区域。不会将代码合并到 GitHub Pages 正式 `main`，不触碰真实备份、真实设备登录凭据、Netlify Database、Functions 的 POST 或 Blobs。

### 实现

- `src/services/syntheticDeviceKeyStore.ts`：必须满足 `VITE_ISOLATED_LAB=1` 且位于独立测试域名（含其预览域名）或本机 HTTPS 可用的开发地址才允许运行；其它环境拒绝。
- 通过 `crypto.subtle.generateKey({name:'ECDSA',namedCurve:'P-256'}, false, ['sign','verify'])` 生成**不可导出的私钥**，与公钥配对。浏览器用单独的 `personal-state-observer-synthetic-device-key-v1` IndexedDB 保存 CryptoKey（结构化克隆）及公钥、随机设备 ID 和创建时间；**与**包含虚构每日记录的 `personal-state-observer-fixture-lab-v1` 分离。
- 首次生成前检查原有槽位；采用 IDB `add` 拒绝覆盖已有密钥。页面刷新后只能读取原密钥，不自动再生成。
- 「验证本机签名（不联网）」对随机数据签名并用存储的公钥验签，显示公钥 SHA256 的前 16 个十六进制字符**作为便于人工核验的简短指纹**；它不是防碰撞级别的身份认证，也不代表云端配对。
- 「清除未配对测试密钥」须用户在浏览器确认对话框中明确同意；只删除独立密钥库单条记录，绝不修改每日记录库。**如果以后已经真正配对，不能沿用这个删除方法代替服务器撤销。**
- 页面明确显示**服务器尚未配对、云端同步未开启、非手机发布权限**，不会向服务器发送公钥、私钥、设备 ID、签名或用户记录。

### 安全与兼容性边界

1. WebCrypto 的 `extractable:false` 阻止通过 WebCrypto API 导出私钥，**不等于受硬件安全模块保护**，不能保证被恶意脚本控制时无法调用签名功能。
2. Safari IndexedDB 存储可能因用户删除网站数据、浏览器政策、隐私模式或迁移 origin 而丢失。必须经过真实 iPhone 的创建、刷新和重新验签才可判定 Safari 兼容通过。
3. 这一阶段没有账户绑定公钥、服务端设备登记/撤销和一次性挑战机制；此前 PR #9 只是后台原型，仍未部署，且其 P-256 签名协议不是本轮自测文案中的“已配对”。
4. CryptoKey 永不加入日常 JSON 备份或加密数据备份；用户不能从普通 JSON 恢复浏览器密钥。将来正式配对必须考虑换机恢复和密钥吊销。
5. 同一测试网站上的电脑也能生成**本地试验密钥**，但服务器没有登记任何设备，因此**没有设备拥有发布权限**。验证本机私钥 != 验证 Netlify 账户身份。

### 自动化验收

`tests/isolated-lab.browser.mjs` 在全新 Chromium 浏览器上下文中使用虚构数据测试：

- 手动生成本机 P-256 密钥，存储中的私钥为真正 `CryptoKey`、`extractable=false` 且 `exportKey` 报错。
- 本机签名/验签通过；页面刷新后设备 ID、公钥指纹保持一致且签名仍可用。
- 点击按钮不发起 POST 或任何 Functions/API 请求。
- 生成、验证、清除钥匙均不改变虚构的每日记录；未通过确认不能清除；备份对比/加密恢复现有回归仍通过。
- 正式 `npm run build` 与合成 `npm run build:testlab` 都能构建。
- GitHub CI 使用新的临时浏览器、**绝不访问用户 Netlify 数据库**。

### 后续的独立开发门槛

1. iPhone Safari 真机证明独立测试站的 CryptoKey 刷新后可重用；如果失败，保留无配对状态并修复。
2. 设计经用户明确确认的**手机设备登记**：后台登录 Netlify 身份后，手机仅提交公钥+设备 ID，必须经明确二次配对确认；不允许登录即登记、电脑自行覆盖已有手机。
3. 服务端保存已登记公钥，按 PR #9 的 P-256 协议签名挑战校验；同一账户只能有一个可发布设备，电脑未登记则只能读。
4. 为用户提供独立的设备撤销和更换流程；在此之前禁止真实上传。
5. 必须从完全独立的虚构测试数据端到端验收加密版本 CAS 后，才能讨论迁移原 GitHub Pages 的真实手机记录。
